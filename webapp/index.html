Control Hub Setup

Upload the downloaded manifest in Control Hub, then copy the Client ID, Client Secret, and activation code. Use a shared-mode Webex device in a workspace. Personal-mode devices do not send these notifications.

  1. On Create Integration, click Download manifest to save the JSON file.
  2. In Control Hub go to Workspaces > Integrations. Choose Add integration or Upload integration and select the downloaded file.
  3. Copy the Client ID and Client Secret. This demo keeps them in browser memory for the session only. They are not saved or written to disk.
  4. Open the new integration, choose Activate, and copy the activation code. It is a JWT that this app decodes for oauthUrl, appUrl, and a redacted refreshToken.
  5. Continue on Activate & Monitor and paste the three values. Click Activate & Monitor when you are ready.

Activate and Monitor Integration

Paste the Client ID, Client Secret, and activation code from Control Hub. Optionally show the decoded JWT payload. Click Activate & Monitor to exchange the refresh token for an access token, look up workspace names, activate long polling, and stream device xStatus and xEvent notifications.

Kept in browser memory only for this session. It is not saved or written to disk.

Monitoring is active. Click Stop monitoring to show Client ID, Client Secret, and Activation Code again.

How activation works

Click Show requests for a detailed breakdown of the HTTP requests this step makes.

1. Get an access token

HTTP POST to the oauthUrl from the activation payload, exchanging the refresh token for an access token. Repeated automatically whenever the token is close to expiry.

2. Activate the integration and enable long polling

HTTP PATCH to the appUrl, setting provisioningState to completed and enabling the notification queue. The response includes the poll URL used below.

3. Discover workspaces

HTTP GET against the Webex Workspaces API, paginated using the response Link header, used to show workspace names on received notifications. Queried once the integration is activated, not on every device search.

UI Extensions Demo

Search for devices and install a clickable UI Extension Panel (Action Button). This demo will monitor for the clicked events triggered with the matching Panel ID and display an alert on the device.

How discovery & the panel save work

Click Show requests for a detailed breakdown of the HTTP requests these actions make.

1. Discover devices

HTTP GET against the Webex Devices API, filtered to type=roomdesk and capability=xapi so only devices that can run the demo panel are listed.

2. Save the demo panel (Cloud xAPI)

HTTP POST to the device's Cloud xAPI command endpoint, running UserInterface.Extensions.Panel.Save with the panel XML as the request body. Sent when you click Save demo panel above.

3. Remotely trigger the panel click (Cloud xAPI)

HTTP POST to the device's Cloud xAPI command endpoint, running UserInterface.Extensions.Panel.Clicked with the panel's ID so a click can be triggered without physically tapping the device. Sent when you click Trigger panel clicked above.

4. Remove the demo panel (Cloud xAPI)

HTTP POST to the device's Cloud xAPI command endpoint, running UserInterface.Extensions.Panel.Remove with the panel's ID to delete the button from the device. Sent when you click Delete panel above.

How long polling works

Click Show requests for a detailed breakdown of the HTTP request this makes.

Long poll for notifications

HTTP GET against the queue poll URL. Each response can include device messages and a new poll URL, and this repeats for as long as monitoring runs.
